# AnyoneCanPace

Mobile-first PWA for volunteer pacers (AnyoneCanRun by Les Stooopids). React 19 + TypeScript + Vite 8 + plain CSS + vite-plugin-pwa. No analytics or tracking. Optional accounts are being built (`design/backend-v1-spec.md`, README "Accounts"): off on live until launch.
The app always opens on the mode picker (`src/Root.tsx`, no mode is remembered; the exceptions are `?sunday`, `src/lib/sundayLink.ts`, which opens Stooopid Sunday and then cleans the address, and a shared route link `?route=<id>` from SHARE ROUTE on a route page, `src/lib/routeLink.ts`, which opens that route's page; every route page keeps `?route=<id>` in the address while open, so it can be copied from the address bar and a reload stays on it; the library has none), in this order: **Stooopid Sunday Dashboard** (`src/dashboard/`, lazy-loaded; Sunday run first, then "Running another time?", then the story), **ACR Run/Walk Timer** (`App.tsx`), **Route Library** (`src/sixk/`, lazy-loaded).
Live: https://anyonecanpace.pages.dev/ · Beta: https://anyonecanpacebeta.pages.dev/ (both Cloudflare Pages; GitHub Pages is off so no address leads to the owner's personal github.io site) · Full details, limitations and the **V2 To-Do List** are in README.md.

## Commands
- Node and npm live in `~/.local/bin`. If `npm` is "not found", use `~/.local/bin/npm` or `source ~/.zshrc`.
- `npm run dev` → http://localhost:5173/anyoneCanPace/
- `npm test` (Vitest), `npm run typecheck`, `npm run build` (also runs `scripts/check-bundle.ts`). Run all three before committing.
- `npm run preview` serves the production build. Service workers only register there, not in dev.
- `npm run routes` rebuilds `src/data/routes/` from `routes/*.gpx` (keeps hand-edited name/turns/notes/advisories; `--offline`, `--reset-turns`). `npm run map` re-cuts `public/maps/montreal.pmtiles` (then bump `MAP_VERSION` in `src/sixk/map/offlineMap.ts`).
- Route editor (dev only): `npm run dev`, open `/anyoneCanPace/?edit`. Adds routes from a GPX (cleaned to track points only), edits details, tags, turns (with a map), advisories and review status, deletes routes (to `.cache/route-editor-trash/`). Writes the same files you'd edit by hand; review and commit as usual. README "Route editor".
- Simulated run (dev only): `npm run dev`, open `/anyoneCanPace/?sim` (`?sim=pi-day`, `&away=300`, `&speed=10`). `src/dev/simulateGps.ts` replaces `navigator.geolocation` and adds a RUN / speed / GO OFF / restart panel; `main.tsx` only loads it when `import.meta.env.DEV`, so it never ships.
- Dev-only pages, same pattern: `?duck-sheet` (every outfit scenario in `src/weather/scenarios.ts` on the dressed duck, plus a playground) and `?meeting-map` (draws the meeting point on the offline map and SAVE TO REPO writes `src/assets/story/meeting-map.webp` + `src/data/meeting-map.json` through the dev-server plugin `scripts/vite/saveMeetingMap.ts`; re-make it when `event.json` or the map changes, a test checks).
- GPS needs HTTPS: `npm run dev:https` (self-signed, `.cache/dev-cert/`) or a Cloudflare/ngrok tunnel. Scripts are `.ts` run by Node directly. Node 26 is pinned in `.nvmrc` (CI, deploy and `engines` use it).

## Layout
- `src/timer/engine.ts`: pure interval logic (start/pause/resume/skip/sync). No clocks, no React.
- `src/timer/clock.ts`: monotonic clock (`performance.now()`), corrected for device sleep using `Date.now()`.
- `src/hooks/useIntervalTimer.ts`: React binding. 250 ms display ticks, catch-up on visibility change, events.
- `src/hooks/useWakeLock.ts`, `src/lib/cues.ts` (Web Audio beeps + vibration), `src/lib/prefs.ts` (localStorage).
- `src/components/`: TimerDisplay, EditPanel, MenuSheet, ModePicker. `src/App.tsx` composes the timer page. Styles in `src/styles.css`.
- `src/nav/`: pure route following (`geo`, `route`, `tracker`, `banner`). All tunables in `nav/constants.ts`. No clocks, DOM or `navigator`: fixes carry their own timestamps.
- `src/sixk/`: Route Library UI (folder name kept from when it was "6K") (SixKMode, Library, LibrarySettings, RoutePage, FollowView, useRouteNav, `sixk.css`). `describe.ts` is pure: terrain words, time at a pace, `ROUTE_TAGS` (loaded from `src/data/route-tags.json`, checked by `validateTagList`; `FILTER_TAGS` can't be removed), filters, `validateDescription`. The library pace (one of `PACE_PRESETS`, min/km; an old saved value snaps with `nearestPace`) and sort order (`sortRoutes`: A–Z, distance, elevation gain) are saved (`prefs.ts`); its filter is never saved. Routes tagged `testing` are hidden unless "Testing routes" is on in Library settings (`visibleRoutes`; off on every visit; a shared link still opens one). `src/sixk/map/`: RouteMap (MapLibre + PMTiles), `mapStyle.ts`, `offlineMap.ts` (whole map file in Cache Storage). `src/hooks/useGeolocation.ts`.
- `src/weather/`: pure weather logic. `forecast.ts` (GEM URL + parsing), `outfit.ts` (rules from `design/weather-v1-spec.md`: clothes follow **air temperature** only, tables `CUTOFFS`/`ACCESSORIES`/`WIND`/`WET`…, one outer layer, `drawn` = what the duck wears), `indices.ts` (EC wind chill, humidex; warnings only), `runTime.ts` (default hour, daylight, outfit input), `cache.ts`. No UV or sunglasses (removed on purpose). `src/event/event.ts` + `src/data/event.json`: the weekly run (Sunday, meet 10:00, start 10:15, Café Tranquille), `nextRun(now)` in Montréal time, `mapsLink()`. `src/story/`: Sunday Instagram story: `snapshot.ts` (frozen forecast + outfit + event at MAKE STORY; preview and saved PNG come from it), `layout.ts` (pure 1080 × 1920 draw lists for two pages, the poster with the big duck and the map page "Lost? Find your Flock!" with the meeting-map and the `meeting-photo.webp` photo, safe area 220–1700 px, monospace widths), `render.ts` (Canvas → PNG, lazy), `StoryDialog.tsx` (preview, SHARE via `navigator.share({files})`, SAVE IMAGE, REMAKE). `src/dashboard/`: DashboardMode, useForecast, SundayRun (COPY MAP LINK, MAKE STORY), `duck/art.ts` (`duckImages`: the one duck composer, also for the story), `dashboard.css`.
- `src/dev/routeEditor/`: the dev-only route editor. Pure rules: `edits.ts` (editable fields, turn/advisory checks, review resets), `turnEdit.ts`, `review.ts`, `deletion.ts`. `server/` is a Vite plugin (`apply: 'serve'`) with the file API (`api.ts`) behind `guard.ts` (loopback address and host, editor header, same-origin writes); it's type-checked by `tsconfig.node.json`, not the app config. `scripts/check-bundle.ts` fails the build if editor code reaches `dist/`.
- `scripts/`: `build-routes.ts` (+ pure `lib/process-route.ts`, `lib/elevation.ts`, `lib/turns.ts`), `cut-map.ts`, `check-bundle.ts`, `dev-cert.ts`. `routes/`: source GPX, `routes.config.json`, `cache/` (elevation, streets, proposed turns), `review/` (turn and elevation review reports: suggestions, not verified).
- Tests: `src/**/*.test.ts(x)`, `scripts/**/*.test.ts`. `App.test.tsx` drives the real timer UI with fake timers (keep it untouched). `Root.test.tsx` covers the picker and Route Library UI with mocked geolocation and a stubbed RouteMap. `src/nav/testing/replay.ts` replays synthetic GPS tracks.

## Rules that must not break
- Timing: while active, store only `endsAt` and derive remaining = `endsAt - now`. Never count ticks down. New intervals start at the previous boundary, not at "now".
- Duration edits apply to the **next** occurrence of that phase. Never reset, pause or restart the running interval.
- No auto-reload mid-session. The SW uses `registerType: 'prompt'`; `Root` makes the app's only `useRegisterSW` call (with `SW_OPTIONS`, `src/lib/swUpdate.ts`, which reloads on activation only when no timer session or route is live) and shares it through `AppUpdateContext` (`src/lib/appUpdate.ts`). Every screen (home and each mode) shows the same `UpdateBanner`, hidden while a timer session is running or paused or a route is being followed. It checks again for a new version when the app starts and whenever it comes back into view (at most once a minute). Dev-only `?update-banner` shows the banner without a real update.
- Don't replay missed cues after suspension. Only cue transitions under 2 s old while the page is visible.
- Reset/End stays in the Settings sheet behind a two-tap confirm, away from the main controls.
- Accessibility: touch targets ≥ 44 px, phase text never conveyed by colour alone, announce phase/pause changes (not every second), respect reduced motion.
- No new heavy dependencies (no state libraries, UI kits or analytics). **Exception:** MapLibre GL JS and the PMTiles reader, for the 6K mode only, and only lazy-loaded. `scripts/check-bundle.ts` fails the build if either reaches the first-load bundle. Build-time-only dev dependencies for scripts are fine if justified.

## Accounts rules (design/backend-v1-spec.md)
- Server code: `server/` (`handler.ts` API, `db.ts` the only SQL, prepared statements only, `auth0.ts`, `routes.ts` checks for personal routes built on the device, `lookups.ts` elevation/street proxies that pass answers through unparsed), Pages Function `functions/api/[[path]].ts`, D1 migrations in `migrations/`. Local dev runs the same handler through `scripts/vite/accountsApi.ts` on `node:sqlite` (`server/dev/sqliteD1.ts`) with `.dev.vars` (dev Auth0 tenant only). Tests: `server/handler.test.ts`.
- Accounts UI only where `__ACCOUNTS__` (dev server or `ACCOUNTS=1`); the YOUR ACCOUNT entry is only on the home screen, never mid-run. The service worker never answers `/api/` (`navigateFallbackDenylist`).
- Personal routes are only ever read or written with the owner's ID (`WHERE owner_id = ?`); route files live in D1, R2 is only for the map. Someone else's data is "not found", never "forbidden". Writes check `Origin`. Never log tokens, emails or recovery codes. Store no email in D1. Admin = `ADMIN_AUTH0_ID` only, never a database role.

## Route rules
- Progress is forward-only and matched in a window around current progress (it grows during GPS gaps). Never snap to the globally nearest point: routes overlap and a loop's start and finish are close. Off route, rejoining beyond the window (`tryRejoinAhead`/`rejoinOptions`) is ahead-only, needs the direction of travel to match exactly one leg, and never assumes the finish stretch; otherwise **JOIN AT** decides. The off-route banner's distance and direction point to the closest route still ahead (from progress on; beyond the next km, not past 90 % until 90 % is covered), never behind.
- One cue per GPS fix, by priority: finished > turn now > off route > heads-up (`src/sixk/navDelivery.ts`). Announcements come from each event's own turn and `distanceM`; a heads-up only fires for the next pending turn and a close next turn is folded into the "now" ("Left now, then right in 60 metres").
- GPS gaps are measured from the last *usable* fix (`lastGoodFixAt`, accuracy ≤ 60 m); `lastFix` is raw position only. `gpsHealth()` drives the "GPS lost / too rough" alert and greys the banner.
- Joining: near the start the beginning wins and a later leg (loop finish) is never assumed; several legs elsewhere wait for direction of travel or an explicit JOIN AT x KM (`joinOptions`/`joinAt`).
- Routes carry `verification` (unverified / desk-reviewed / field-verified; reviewed needs reviewer + date) and a `geometry` fingerprint. Never mark a route reviewed without a real check. A geometry change stops `npm run routes` until `--reset-turns`. The route editor saves a review on its own (never with turn changes), resets a reviewed route when turns or the start street change, and never edits the reviewed list in `verification.test.ts`: a person adds that line.
- GPX uploaded through the route editor is rewritten by `scripts/lib/sanitize-gpx.ts` (lat/lon/ele only: no times, heart rate, waypoints or names) before it reaches `routes/`, because the repo is public. Keep it that way.
- Turn cues fire once per stage (heads-up ~150 m, now ~30 m). Turns passed in a GPS gap (>10 s without a fix) are skipped silently; a turn jumped over between close fixes (≤60 m past) still gets a late "now". Cue only for fresh fixes while visible; never replay.
- Vitest's on-disk module cache is off (`fsModuleCache: false`) because it missed new routes picked up by `import.meta.glob`.
- Off route: >30 m for 5 s → banner, the confused duck (`duck-runner-lost.webp`, source `design/duck-confused.webp`) with a "?", "Going rogue?" dialog. Going rogue calms the banner but keeps the confused duck until back on route. Started but not yet joined and >30 m away also shows the confused duck (`duckLost` in `tracker.ts`), with no dialog or buzz. Finish only after 90 % covered and near the end. Ending a route needs the menu and two taps.
- Privacy: GPS positions live in memory for the current route only. Never store, log or send them.

## Dashboard rules
- The only runtime request to another site is the GEM weather request in `forecast.ts`, with fixed Montréal coordinates, never the user's location. Fetch only when the dashboard opens or comes back into view and the saved copy is >30 min old, or on REFRESH. Keep the last forecast in localStorage and always show when it's from; fall back to "Check outside".
- The outfit is always shown as text; the duck is decorative (`aria-hidden`). Credit Open-Meteo (CC BY 4.0) and Environment Canada's GEM on the page.
- Dressed duck: `src/dashboard/duck/` (`pieces.ts` has `LAYER_ORDER` and is pure; `DressedDuck.tsx` stacks `src/assets/duck-outfit/<item>.webp` (512 px, transparent, drawn in place; art brief in `design/duck-art-brief/`) over `duck-base.webp`). The duck draws `outfit.drawn` (a subset of the written list); every piece it can draw needs a file (a test enforces it). Falling rain/snow is CSS, off for reduced motion.

## Advisories rules
- `src/data/advisories.json` is hand-edited by pull request. `src/advisories/notices.ts` is pure (filtering by route and date, expiry, validation). A test validates the real file. Always show "Last checked".
- Automated sources (a road-closures file from a scheduled Action, Environment Canada warnings) plug in as more `Notice[]` lists with a `kind`. The closures Action is **researched, not built**: ask before adding workflow files (they need the `workflow` scope and the user's go-ahead). Montréal `info-travaux` facts and noise numbers are in the README.
- Credit "© OpenStreetMap contributors" and the route's source (e.g. On The Go Map) in the UI. Raw GPX stays in `routes/`; only processed files ship.
- The duck is the route position marker (no progress ring there) and always sits at the GPS fix, off route too; off route the camera keeps it centred and zooms out (down to zoom 14, `sixk/map/camera.ts`) to also show the route point at current progress; BACK TO DUCK always re-centres on it. Banner text always states the direction; icons and colours are extras.

## Paths and deploy
- Cloudflare Pages serves the app from the root of its own domain: `vite.config.ts` gives `base` `/` when `CF_PAGES` or `BASE_PATH=/` is set (`BASE_PATH=/pace/` builds for a sub-path; with neither, the base comes from `GITHUB_REPOSITORY` or the git remote, e.g. `/anyoneCanPace/`). `public/_headers` sets cache headers. In `index.html` reference public files as `/file.png`, never `%BASE_URL%` (Vite adds the base itself).
- Cloudflare builds `main` (live project `anyonecanpace`) and the beta repo's `main` (project `anyonecanpace-beta`, `BETA=1`) with `npm run build`; its env vars are `NODE_VERSION=26` and `BASE_PATH=/`. The build includes the typecheck but not the tests: run all three locally and rely on CI for pull requests. `.github/workflows/deploy.yml` (GitHub Pages) is disabled on the main repo and GitHub Pages and Actions are off on the beta repo; remove `deploy.yml` when convenient. Pull requests run `.github/workflows/ci.yml` (typecheck, test, build, `npm audit --audit-level=high`), which never deploys. Actions are pinned to verified commit SHAs (comment = release). Repo is public.
- Feature work happens on branches. Never merge into `main` or open PRs unless asked.
- Pushing workflow-file changes needs gh's `workflow` scope (`gh auth refresh -s workflow`).
- **Ask before pushing.** Committing locally is fine, but before any commit (this repo or the beta), ask whether the update banner should carry a short "what's new" note for users: propose a sample, and wait for approve / edit / "no details needed".
- Beta channel: remote `beta` = github.com/ShereenElaidi/anyoneCanPace-beta (deploys to `anyonecanpacebeta.pages.dev` through Cloudflare). Same code; `BETA=1` or a base path containing "beta" sets `__BETA__` (BETA tag, "AnyoneCanPace Beta" name/title). Pushing a branch to `beta`'s `main` makes Cloudflare deploy it there without touching the live app. Still ask before each push.
